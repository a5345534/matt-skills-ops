# Parallel workflows serialize at the Target branch

Matt Auto permits multiple independent Active workflows for one canonical GitHub repository and Target branch, provided every Workflow home uses its own local checkout and holds an exclusive, renewable Workflow coordinator lease. Each workflow opens its own direct Target-branch PR once its internal work is complete; implementation capacity is shared fairly across workflows, while each workflow's Integration remains isolated.

Final delivery is automatic but serialized by a GitHub-backed Target-branch merge queue. Queue candidate facts live in each workflow's manifest and are ordered FIFO when the current PR head passes required checks; a conditional-push remote-ref lease, heartbeat/TTL, and fencing token make the refresh → verify → PR update → merge sequence exclusive across sessions. A holder releases the lease while remote PR CI runs, refreshes and rechecks when the Target branch advances, and can merge only with both the current lease token and the validated Target-branch SHA. Refresh conflicts use the existing Conflict resolution worker; deterministic failures fail closed and leave the queue, while transient infrastructure failures retry with bounded backoff. This rejects shared local checkouts, arbitrary Active-workflow selection, manual merge ordering, comment-based distributed locks, and stale-base merges.
